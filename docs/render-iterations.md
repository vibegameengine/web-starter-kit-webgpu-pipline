# Итерации развития Webgiya

Актуальная цель: [виртуальные текстуры и единый освещённый мир](render-quality-goal.md). Каждый шаг даёт работающий прирост. Проверка отвечает на вопрос этого шага.

## 01 — Запечённая статика и живые приёмники вместе

**Результат:** `?mode=hybrid` оставляет static lightmap на поверхностях с bake и запускает существующий lifecycle/integrator/resolve Webgiya для движущихся объектов. Нижняя часть шара получает GI. В UI доступен режим hybrid; старые surfel/lightmap остаются для сравнения.

**Что соединено:** bake явно запрашивает сохранение live surfels; закреплённый atlas и свободный хвост пула работают одновременно. Resolve получает состояние закрепления от SurfelGI вместо глобального URL-флага. FrameGraph использует маску конкретного приёмника в alpha существующего MRT, чтобы не добавить полный realtime indirect поверх baked indirect. Дополнительного render target для маски нет.

**Один проверенный риск:** переключили только realtime-вклад в одной неподвижной сцене. 580516 внутренних пикселей запечённых поверхностей остались совершенно одинаковыми; 6200 пикселей незапечённого приёмника изменились. Это проверка отсутствия двойного света, не оценка физической точности или общего FPS. На контрольном кадре закреплено 148480 surfels, живых после перемещения/resize — 15, ошибок браузера — 0.

Команды:

```powershell
npm run dev
node scripts/check-hybrid.mjs
npm run typecheck
npm run build
```

Лично просмотрены свежие headed-кадры [с GI](../shots/hybrid-iteration-01/on.png), [без realtime GI](../shots/hybrid-iteration-01/off.png), [после перемещения](../shots/hybrid-iteration-01/moved.png) и [после resize](../shots/hybrid-iteration-01/resized.png). Typecheck и production build проходят. Существующее предупреждение Inspector о frame scope и предупреждение Vite о размере bundle остаются.

**Границы шага:** это маршрутизация приёмников. Статический indirect пока не меняется от движущегося препятствия; stale-light invalidation не завершена. На движущемся шаре в тени остаётся недостаток пространственной детализации света. Одного этого режима недостаточно для завершения общей цели. Виртуальные страницы, сохранение bake, полноценная дешёвая модель динамики и общие ограничения масштаба ещё впереди.

**Следующий полезный шаг:** подключить страничное чтение готовой lightmap с постоянно доступным грубым fallback; затем загрузку/вытеснение страниц. Не начинать новую кампанию измерений.

## 02 — Замороженная статика по умолчанию и страницы без чёрных дыр

**Дефект:** default `surfel` прогревал покрытие через ракурсы камеры. Полный `frozen` останавливал заполнение пропущенных поверхностей: на внешней красной стене оставался чёрный центр с пятнистым краем. Это не готовая lightmap.

**Результат:** default теперь `hybrid`, полный статический UV-атлас запекается при старте. UI показывает `static frozen` как состояние готовой статики; live GI остаётся для динамических приёмников. Старый полный freeze доступен только в явно выбранном экспериментальном `surfel`. Разделение экрана диагностикой выключено по умолчанию. Неполное заполнение атласа из-за исчерпания пула завершает bake ошибкой вместо публикации заведомо дырявой карты.

**Страницы:** готовая карта читается через ограниченный кеш массива текстур (8 слотов по умолчанию), integer page table, соседние gutters и переход к доступному mip. Грубая карта 128² постоянно доступна. CPU выбирает страницы по видимым треугольникам и их экранной площади; очередь ограничена, upload — максимум 2 страницы за кадр. Одностраничный staging + GPU copy обходят отсутствие частичного upload массива в r182. В r182 explicit-LOD filtered array sampling теряет layer в WGSL, поэтому физический кеш с единственным mip использует implicit sampling с layer; виртуальный LOD выбирается отдельно.

**Проверка задачи пользователя:** `node scripts/check-frozen-static.mjs` открывает default hybrid, поворачивает камеру к внешней красной стене, очищает все детальные страницы и приостанавливает их загрузку, затем возобновляет загрузку и перемещает шар. Лично просмотрены `shots/frozen-static/inside.png`, `outside-fallback.png`, `outside-resident.png`, `outside-moved.png`: чёрной дыры на стене нет даже при 0 резидентных страницах. Произошёл ровно 1 bake; GPU-пиксели готового fallback остались побитно прежними; 148480 статических surfels закреплены. Ошибок браузера нет. Это проверка конкретного дефекта, не заявление о физической точности или производительности всего рендера.

**Границы:** страницы пока загружаются из RAM, исходная полная bake-текстура и пул всё ещё выделены на GPU; общего сокращения памяти пока нет. Bake не сохраняется между перезагрузками страницы. Полноценная фильтрация произвольных UV charts, диск/сеть, освобождение bake-ресурсов и более качественная дешёвая динамика остаются следующими отдельными шагами. В экспериментальном `surfel` полный freeze всё ещё способен заморозить неполное покрытие; он не используется по умолчанию.

Итоговые проверки: `typecheck`, production build и `git diff --check` прошли. Проверка приёмников после подключения страниц также прошла: 580516 внутренних пикселей статики не изменились при отключении realtime GI, 6199 пикселей динамического приёмника изменились; ошибок браузера нет. Предупреждения Inspector и размера production bundle остаются.

## 03 — Повторное использование bake после перезапуска

**Результат:** default hybrid сохраняет bake в `public/bakes/<key>.bin` и краткие метаданные `.json`. При следующем запуске подходящий файл восстанавливает lightmap и закреплённый surfel-кеш без UV raster bake и без интеграционных проходов. Динамика получает прежний свет, radial-depth visibility и обученное распределение направлений через наследование от статических surfels. Восстанавливаются оба буфера моментов, стек свободных слотов и его граница, чтобы динамический allocator не перезаписал статические данные.

**Пригодность файла:** SHA-256 ключ учитывает исходный код, lockfile, статическую геометрию/UV/индексы/инстансы, преобразования, параметры материалов и пиксели diffuse/emissive maps, источники света, environment, blue noise и настройки bake. Камера исключена, кроме явно запрошенного экспериментального `bakecam=view`. Хеш исходников пока консервативный: изменения любого файла в src инвалидируют файл. Формат имеет версию, контроль размеров и SHA-256 checksum. Повреждённый файл отвергается, приложение выполняет и сохраняет новый bake. `re-bake now` явно пересчитывает, даже если файл подходит; `?bakeCache=0` отключает сохранение/загрузку для проверки самого baker.

**Хранение в проекте:** development-only middleware пишет только имена из 64 hex-символов в `public/bakes`, принимает same-origin PUT и публикует файл переименованием временного файла. Данные исключены из HMR: сохранение не должно перезапускать приложение. GET обслуживается явно, потому что Vite иначе не видит новые файлы в исключённой директории. Production build копирует готовые public-артефакты и только читает их. Если сохранить нельзя, рассчитанное освещение продолжает работать, а причина доступна в `__audit.bakeCache()`.

**Исправленная зависимость:** рост GPU-пула раньше создавал integrator с дефолтными env/bounce/albedo настройками. Теперь заданные параметры сохраняются при пересоздании, в том числе при восстановлении bake.

**Проверено:** `node scripts/check-bake-persistence.mjs` запускает отдельные процессы Chrome. Cold: 1 bake и сохранение. Следующий процесс: 0 bake, восстановлены 148480 pinned surfels; GPU-пиксели fallback совпали побитно, 580516 внутренних пикселей статических поверхностей beauty совпали. `sun=0` дал другой ключ и отдельный bake. Искусственно повреждённый файл был отвергнут по checksum и заменён новым расчётом. Ошибок браузера нет. Лично просмотрены свежие headed-кадры `shots/bake-persistence/baked.png`, `loaded.png`, `sun-off.png`, `recovered-outside.png`, `preview.png`.

Typecheck и production build прошли. Production preview также восстановил тот же ключ без bake и ошибок; для повторения после build: запустить `npm run preview -- --port 5190`, затем `$env:BAKE_BASE_URL='http://127.0.0.1:5190'; node scripts/check-bake-persistence.mjs --saved-only`.

**Границы и следующий шаг:** текущий файл Cornell занимает 101597248 байт и загружается целиком. Это точное сохранение существующего состояния, ещё не масштабируемый формат мира. Следующая полезная итерация — сжатые независимо загружаемые страницы и отдельное размещение статического освещения для динамических запросов; текущая пропорция «один runtime surfel на texel» слишком дорога для большого мира. Локальные изменения пока выбирают другой полный bake, не пересчитывают только затронутую область. Дефекты дешёвой модели динамики и прочие требования общей цели остаются открытыми.

## 04 — Сжатые страницы с загрузкой по запросу

**Результат:** при сохранении проекта публикуются `<key>.stream.json` и независимые gzip-ресурсы `blobs/<sha256>.chunk`: fallback, детальные страницы с gutters и четыре массива статического surfel-кеша. Нейтральное расширение существенно: preview-сервер автоматически добавлял Content-Encoding для `.gz`, а браузер тогда распаковывал данные до нашего декодера. Ресурсы именуются по содержимому, проверяются по размеру и checksum, манифест заменяется атомарно после записи всех его данных. Страничный builder общий для RAM-пути и server packing — mip и gutters не реализованы двумя расходящимися алгоритмами.

Default hybrid после перезапуска читает манифест и fallback, восстанавливает нужный текущей модели динамики статический кеш, затем подгружает только затребованные lightmap-страницы. Полная lightmap и CPU mip-цепочка не создаются на этом пути; полный GPU atlas тоже не выделяется. Старый `.bin` остаётся для совместимости и `vt=0`, при наличии корректного манифеста default не запрашивает его. После первоначального авторского bake данные ещё находятся в RAM: переход к HTTP-источнику происходит при следующем восстановлении.

В очереди не более 4 запросов, upload не более 2 страниц за кадр. Смена набора видимых страниц отменяет ненужные запросы. Clear/dispose отменяют запросы; поколение и проверка владельца исключают публикацию запоздалого ответа. Неудачная проверка или загрузка сохраняет fallback, повторы идут через 1/2/4…30 секунд. Gzip распаковывается через DecompressionStream с ограничением выходного размера, после чего проверяется SHA-256. HTTP-кеш может повторно использовать неизменяемые ресурсы.

**Проверка конкретного результата:** `node scripts/check-page-streaming.mjs` создаёт bake, открывает новый Chrome, задерживает все детальные страницы, поворачивает камеру, разрешает загрузку, возвращает камеру, затем подсовывает страницы с неверным checksum и восстанавливает ответы. На маршруте затребовано 11 из 20 уникальных страниц; произошло 3 вытеснения, повторного bake и запросов `.bin` — 0. При задержке и повреждении было 0 резидентных страниц и видимый свет из fallback. После загрузки 580516 внутренних пикселей статики совпали с RAM-путём без отличий. Повреждение не приводит к запросам каждый кадр; автоматическое восстановление проходит. Ошибок браузера нет.

Лично просмотрены свежие headed `shots/stream-pages-before.png`, `shots/stream-pages-first.png`, `shots/page-streaming/outside-delayed.png`, `outside-streamed.png`, `failed-fallback.png`, `recovered.png`. Typecheck, production build и diff check прошли. Production preview с `check-bake-persistence.mjs --saved-only` проверяет именно `storage=streamed`.

**Размер и границы:** все уникальные сжатые данные последнего bake вместе занимают 54938804 байт против 101597248 байт старого bundle; это размеры артефактов, не замер VRAM или фактического сетевого трафика. Четыре surfel-массива всё ещё загружаются целиком и занимают прежний GPU-пул. Сжатие файлов этого не исправляет. Следующий важный шаг — отделить представление света для динамических запросов от числа texels lightmap, сохраняя видимость и пространственные детали. Полноценное взаимодействие динамики со статическим indirect и большие сцены ещё не завершены.

Production preview после исправления расширения подтвердил `source=saved`, `storage=streamed`, 0 bake и 0 ошибок браузера. Свежий `shots/bake-persistence/preview.png` просмотрен: статика освещена, но на нижнем крае динамического шара виден чёрный контур при малом live-покрытии (3 surfels). Это оставшийся дефект динамического GI, не закрытый проверкой статических страниц; его нужно учитывать в следующей итерации модели динамики.

## Итерация 05 — восстановление покрытия динамических поверхностей

**Дефект:** проверка покрытия учитывала pinned-пробы, которые финальный hybrid gather исключает. Она также использовала геометрический вес без radial visibility, редкую случайную генерацию и запрет новых образцов после 32 соседей. Запечённая плотность влияла на старение живых проб. В результате достаточного покрытия поверхности не было даже после ожидания: промежуточное исправление оставляло 491 пиксель без GI на верхней части шара и через 2,2 секунды.

**Рабочее изменение:** GI G-buffer теперь хранит принадлежность baked receiver в alpha нормали. В hybrid статические поверхности исключены из поиска живых проб и финального динамического gather. Проверка живого покрытия вызывает общий `resolveIrradiance` с теми же пространственными, направленными, временными и radial-depth весами. Pinned-пробы могут дать начальное освещение дочерней пробе, но не засчитываются как живое покрытие и не создают штраф за плотность в lifecycle. Настоящий пробел запрашивает новый образец; голосование ограничивает добавление одним образцом на tile 8×8. Молодым пробам дают завершить начальное накопление, чтобы не создавать дубликаты. Геометрическое удаление «лишних» проб в hybrid отключено: без проверки visibility оно не доказывает избыточность; старение и штраф за живую плотность остаются.

При непрерывном движении обнаружился отдельный первый чёрный кадр: новая проба уже прошла integration, но её fade равнялся нулю. В hybrid она теперь получает минимальный относительный вес 1/4; confidence и visibility продолжают действовать. Это использование рассчитанного образца, без добавления ambient-подсветки.

**Проверка результата:** `scripts/check-dynamic-coverage.mjs` читает coverage alpha только на незапечённой геометрии; фон исключён через GI albedo G-buffer. Сценарий `legacy` воспроизвёл 6208/6208 пикселей без GI в стартовом кадре и 14/26645 в косом ракурсе. Исправленная проверка трёх фиксированных поз дала 0 пропусков; с `GI_CONTINUOUS=1` три кадра непрерывного движения также дали 0 пропусков на 5394, 4799 и 11802 пикселях шара. GPU-пиксели статической fallback-карты совпали побитно во всех случаях. Ошибок браузера нет. Свежие кадры `shots/dynamic-coverage/fixed/` и `fixed-moving/` просмотрены лично.

`check-frozen-static.mjs` повторно подтвердил default hybrid, frozen static, 1 bake при принудительном холодном запуске, неизменную карту после движения камеры/шара и освещённую наружную стену при 0 резидентных детальных страницах. Кадр `shots/frozen-static/outside-fallback.png` просмотрен. `check-hybrid.mjs`: при выключении динамического GI 580516 внутренних пикселей статики не изменились, 6196 пикселей незапечённого шара изменились; движение и resize прошли без ошибок. Typecheck, production build и diff check прошли.

**Граница итерации:** отсутствие coverage holes не означает идеальное освещение. В кадре непрерывного движения `fixed-moving/oblique.png` видна пятнистость GI на шаре. Следующий полезный шаг — устранить её через согласованное освещение и повторное использование данных на движущейся поверхности. Общая grid всё ещё содержит плотный pinned atlas, сканирование ограничено 512 элементами, отдельного компактного поля света для динамики пока нет. Ни качество на всех траекториях, ни масштабируемость всего мира этой проверкой не доказаны. Полный goal остаётся активным.

## Итерация 06 — пробы следуют за движущейся поверхностью

**Причина крупных пятен:** живые пробы оставались на прежних мировых координатах после перемещения шара. Они могли оказаться внутри него и накопить тёмное освещение, а новые участки постоянно требовали новых проб. Нулевое число coverage holes не обнаруживает этот дефект.

**Изменение:** `surfelMotion.ts` сохраняет локальную позицию, нормаль, владельца и birth stamp новой пробы. Перед integration GPU переносит их текущей матрицей меша; обратная транспонированная матрица переносит нормаль. Поиск покрытия и lifecycle обращаются к предыдущей grid по предыдущей позиции приёмника. Gather не смешивает пробы разных зарегистрированных движущихся мешей. Старые radial-depth данные очищаются после перемещения; плавное движение сохраняет историю irradiance, большой скачок/поворот сбрасывает её и guiding. Сброшенная история получает тот же warmup интегратора, что новая проба. Статические pinned-пробы не изменяются.

**Проверка:** `node scripts/check-rigid-surfels.mjs` проходит одну траекторию с переносом и поворотом; `$env:RIGID_SURFELS='0'` включает прежнее мировое размещение. Проверка читает реальные GPU-позиции и anchors, требует сохранения тех же локальных координат у сохранившихся проб и проверяет попадание в геометрию тестового шара. В зафиксированном проходе сохранились и переместились 74 исходные пробы; максимальная ошибка переноса меньше 0,000001 м. Отклонение от идеальной сферы меньше 0,003 м и соответствует её треугольной сетке. В старом варианте пробы оставались до 2,60 м от актуальной поверхности. Конец прохода: 78 живых проб с привязкой против 300 без неё. Это число проб конкретного сценария, не оценка FPS. GPU-пиксели статической fallback-карты совпали побитно. Свежие headed-кадры в `shots/rigid-surfels/attached/` и `world/` просмотрены на одинаковых позах: крупные тёмные пятна заметно уменьшились.

**Цена и границы:** anchors пока выделены на полный pool: 32 байта на слот, 8 MiB при 262144 слотах плюс 512 байт матриц в сцене с одним движущимся мешем. Два GPU-прохода переносят существующие anchors и присваивают новые; дополнительная перестройка grid не нужна. Поддержаны жёстко движущиеся Mesh с фиксированной геометрией; skinned, instanced, morph и positionNode-деформации сохраняют прежний путь. Компактное статическое поле света для динамики, деформации, signed-коррекция на статике и проверка всех световых переходов остаются следующими задачами. Полный goal не завершён.

**Сохранение:** увеличившийся после параллельной правки UV atlas обнаружил слишком большой несжатый PUT в Chrome debug protocol. Authoring bake теперь передаётся gzip; сервер распаковывает с прежним пределом 128 MiB и проверяет прежний формат/checksum. Файловый формат и страницы не изменены. Для воспроизводимых браузерных проверок HMR-сообщения не доставляются в тестовую страницу: параллельные изменения исходников не должны перезагружать её посреди bake. Рабочий dev-сервер сохраняет обычный HMR.

**Регрессии на общем checkout:** полный `check-bake-persistence.mjs` прошёл cold bake → сохранение → новый процесс → смена солнца → повреждённые данные → восстановление. После загрузки 580516 внутренних пикселей статики совпали без отличий, fallback совпал побитно, повторных bake — 0. Сравнение выполняется после готовности требуемых страниц и завершения их fade; фиксированная задержка раньше могла сравнивать разные стадии загрузки. Новый UV layout из параллельной работы содержит 180850 pinned texels; raw-файл занимает 122831968 байт. `check-frozen-static.mjs` подтвердил неизменность карты и освещённую наружную стену при 0 страницах. `check-hybrid.mjs`: выключение live GI не изменило статику, изменило 6199 пикселей шара; resize прошёл. ## Итерация 06 — лаборатория «пляж-диорама» на гибридном пайплайне

**Задача пользователя:** новая лабораторная сцена по референсу `concepts/beach.png`, на текущем пайплайне освещения, со всеми нужными шейдерами (вода, камни, деревья). Не отдельный стенд: интеграция системы освещения в сложную сцену, включая преломление/каустику и рассеивание в листве.

**Результат:** `http://127.0.0.1:5188/?scene=beach` (Cornell остаётся по умолчанию). Сцена собрана из FSD-сущностей `src/entities/{island,water,rocks,palm,shrub,backdrop,foliage}` и виджета `src/widgets/world/beachScene.ts`. Статика (песчаная плита, стены среза, камни, стволы) разворачивается в общий атлас и запекается surfel-интегратором; листва (пальмы, кусты, wind) — Static для трассировщика, но без lightmap: освещается живыми surfels. Вода и фон вне GI (`userData.giExclude`, слой Debug). Невидимый «студийный пол» — bounce-поверхность только для трассировщика (слой GiStatic).

**Изменения пайплайна:** `lightmapUv.ts` теперь разворачивает произвольные меши (box-quads или проекционные чарты по доминантной оси нормали, одна плотность texel/m, shelf-packer, полутексельный inset); BVH-сборщики учитывают `giExclude`; lightmap умножается на процедурный `colorNode` материала (opt-in `userData.lightmapAlbedo`); трассировщик ослабляет солнечный свет под уровнем воды (`U_GI_MEDIUM`, `hitShading.ts`) — bounce от дна лагуны бирюзовый; medium и углы солнца входят в ключ bake. Тени солнца — три каскада `CSMShadowNode` (разрешение следует за камерой).

**Шейдеры:** вода (`entities/water`) — рэймарч преломлённого луча по текстуре высот острова (28 шагов + бисекция), поглощение по каналам, рассеяние, отражение неба по Френелю, пена по вертикальной глубине, premultiplied-смешивание; песок — зерно/рябь, мокрая полоса, каустика (Worley) как emissive, солнечный свет через воду; стены среза — triplanar слоёв грунта и камня по атрибуту `strata`; камни — процедурная геометрия (плоские срезы, гребни) и triplanar с картой нормалей; листва — vertex colour + просвечивание (`foliage/translucency.ts`).

**Кадры:** `shots/beach/10.png` (hybrid, полный bake), `shots/beach/07-lightmap.png` (split: атлас), `shots/beach/08-hit.png` (рэймарч воды попадает в дно на 100% пикселей). Кадр и референс различаются существенно (mean abs diff 52.5/255 в квадратном кадре); дальнейшее сближение — через gauntlet-раунды (`docs/beach-gauntlet/`).

**Границы:** это интеграция, не финальное соответствие референсу. Открыто: тёмные теневые грани камней, тонкие кроны, плоская вода без преломления дна, шумные стены среза, мягкая тень под островом.
